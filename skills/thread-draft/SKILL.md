# 스레드 글 초안 (thread-draft)

재료: $ARGUMENTS

작업 일지는 기록이고, 스레드 글은 **사람이 멈춰서 읽는 이야기**다. 일지를 요약하지 말고, 그날 있었던 일 중 하나를 골라 내 말투로 들려준다.

## 먼저 읽기

1. `~/.claude/harness/config.local.json` — `threads.dir` (계정 폴더). 비어 있으면 어디에 둘지 묻는다 (workflow §2 "묻는 형식"). WSL `/mnt/c/…` ↔ Windows `C:/…` 는 지금 환경에 맞게 바꿔 쓴다.
2. 계정 폴더의 `voice.md` (내 말투 — 없으면 아래 "처음 쓸 때"), `README.md` (계정 방향 · 글 목록)
3. `~/.claude/harness/shared/threads/` — `writing.md` (글쓰기), `filter.md` (공개 전 거르기), `images.md` (이미지 고르기)
4. 계정 폴더의 `<프로젝트>/README.md` — 연재 번호 · 이미 다룬 이야기 (겹치지 않게)

## 처음 쓸 때

- **계정 폴더가 없으면** 만든다 — `README.md` (틀: `shared/templates/threads-account.md`), `voice.md`.
- **`voice.md` 가 없으면** 사용자에게 말투 재료를 받는다 (평소 쓴 글 · 페르소나 문서 경로 · 질문으로 잡기 중 고르게). 재료를 읽고 **짧은 말투 요약**(틀: `shared/threads/voice.example.md`, 2KB 안팎)을 만든다. 긴 원본은 매번 읽지 않는다 — 요약만 쓴다.
- **프로젝트 폴더가 없으면** `<계정 폴더>/<프로젝트 이름>/README.md` 를 만든다. 프로젝트 이름은 폴더 이름을 기본으로, 처음 한 번 확인한다.

## 진행

### 1. 재료 모으기
지금 폴더(프로젝트)의 `docs/` 에서:
- 작업 일지 `03-worklog/<날짜>.md` — 인자가 없으면 프로젝트 README 의 글 목록에 없는 가장 최근 날짜.
- 그날 나온 결정 기록(D-번호), 그날 커밋 제목 (`git log --since=<날짜> --until=<다음 날> --format=%s`).
- 그날 바뀐 그림 · 화면 (`git log --since=… --name-only` 중 이미지, `docs/01-planning/design/`) — `images.md` 후보.

### 2. 이야깃거리 고르기
`writing.md` "고르기" 기준으로 후보 2~3개를 뽑아 **선택지로 묻는다** (A 가 권장, 기타로 직접). 하루치를 다 넣지 않는다.

### 3. 초안 쓰기
- 고른 이야기로 **2~3안** — 안마다 첫 줄(훅) 방식이 다르게. `voice.md` 말투, `writing.md` 구조 · 길이.
- 안마다 **글자 수를 센다** — 글 하나 500자 안 (`python3 -c "import sys; print(len(sys.stdin.read().strip()))"`). 길면 이어지는 글로 나눈다.
- 연재 번호를 프로젝트 README 에서 이어 붙인다.

### 4. 이미지 고르기
`images.md` 대로 1~n장 — 순서, 고른 이유, 대체 글. 올리기 편하게 **PNG 로 바꿔** 초안 옆 폴더(`<날짜>-<주제>/01.png …`)에 모은다 (Python PIL). 마땅한 게 없으면 "이 화면을 이렇게 찍으면 좋다" 를 제안한다.

### 5. 공개 전 거르기
`filter.md` 대로 초안과 이미지를 다시 본다. 뺀 것 · 바꾼 것을 목록으로 남긴다. 판단이 필요한 것(흥미로운 비용 숫자 등)은 빼지 말고 **물어볼 것** 으로 표시한다.

### 6. 저장하고 보이기
- `<계정 폴더>/<프로젝트>/<날짜>-<짧은 주제>.md` (틀: `shared/templates/thread-draft.md`).
- 계정 README 글 목록과 프로젝트 README 연재 목록에 한 줄 (상태 `초안`).
- 사용자에게는 **추천안 전문 + 나머지 안의 첫 줄 + 이미지 목록 + 물어볼 것** 만 짧게. 고를 것은 선택지로.

### 7. 고른 뒤
- 사용자가 고치면 초안 파일을 고친다. **고친 방향이 말투에 관한 것이면**(예: "이런 표현은 안 써") `voice.md` "고쳐 가며 배운 것" 에 한 줄 더할지 묻는다.
- 올렸다고 하면 상태를 `올림` 으로, 날짜와 함께. 반응(좋아요 · 댓글에서 나온 얘기)을 알려 주면 한 줄 남긴다 — 다음 글의 재료다.

## 하지 않는 것

- 게시 · 예약 · API 호출. 초안까지만 쓴다.
- 없던 일 만들기 — 작업 일지 · 기록에 없는 사실, 숫자, 반응을 지어내지 않는다.
- 원본 일지 · 결정 기록 고치기.

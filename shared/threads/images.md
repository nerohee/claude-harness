# 이미지 고르기

## 후보 찾기 (프로젝트 안에서)

1. 그날 바뀐 그림 · 화면 — `git log --since=<날짜> --until=<다음 날> --name-only` 중 이미지 파일
2. 시안 · 화면 스크린샷 — `docs/01-planning/design/`
3. 그림 자산 — 예: `src/assets/`, `art/`
4. 작업 일지에 언급된 화면 · 결과물

없으면 **찍을 화면을 제안**한다 — 무엇을, 어떤 상태로 (예: "고양이 7마리가 다 나와 있는 메인 화면, 창은 최소 크기로"), 띄우는 명령.

## 고르기 · 순서

- **1~n장**, 이야기에 필요한 만큼. 한 장으로 충분하면 한 장.
- **첫 장이 얼굴** — 목록에서 보이는 그림이다. 가장 눈에 띄고 이야기의 결과를 보여 주는 것.
- 과정 이야기면 **전 → 후** 순서, 시안 비교면 나란히 (한 장으로 합칠지 제안).
- 같은 느낌의 그림을 여러 장 넣지 않는다.
- 장마다 **대체 글**(이미지 설명)을 한 줄로 — 화면 읽기 프로그램 사용자와 검색을 위해.

## 올리기 편하게

- 고른 그림을 초안 옆 폴더(`<날짜>-<주제>/`)에 `01.png`, `02.png` … 순서대로 모은다.
- WebP · SVG 는 PNG 로 바꾼다 (Python PIL). 투명 배경 그림은 배경색을 정해 채울지 제안한다 — 앱 화면색이나 흰색.
- 원본 파일은 고치지 않는다.
- 공개 전 거르기(`filter.md` "이미지에서 볼 것")를 통과한 것만.

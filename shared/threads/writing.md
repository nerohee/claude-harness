# 스레드 글쓰기 — 개발 일지를 읽히는 글로

목표는 "개발 과정을 꾸준히 보여 주는 사람" 으로 기억되는 것. 글 하나가 터지는 것보다 **같은 사람이 계속 재미있게 쓰는 것**이 브랜딩이 된다.

## 1. 고르기 — 하루에 이야기 하나

작업 일지에서 사람들이 멈출 만한 것 하나를 고른다. 좋은 재료:

| 재료 | 예 |
|---|---|
| 실패하고 다시 한 것 | "고양이 그림 122장 뽑았는데 다 뚱냥이였다" |
| 의외의 선택 · 이유 | "Electron 말고 Tauri 고른 이유" |
| 전후 비교 | 1판 → 2판, 시안 a · b · c |
| 숫자 | 걸린 시간, 장수, 시험 개수, 줄어든 용량 |
| 사람 냄새 나는 순간 | 새벽 3시 버그, 결국 처음 안으로 돌아옴 |
| AI 와 일하는 법 | 에이전트에게 맡겼더니 생긴 일, 고친 규칙 |

고르지 않는 것: 진행 상황 나열("오늘은 A, B, C 를 했다"), 설명이 길어야 이해되는 내부 구조.

## 2. 구조

```
첫 줄 — 멈추게 하는 한 줄 (훅)
상황 — 무엇을 하려 했나 (1~2줄)
전환 — 그런데 / 막상 해 보니 (1~2줄)
발견 — 그래서 알게 된 것 · 바꾼 것 (1~2줄)
여백 — 한 줄 생각, 또는 가볍게 던지는 말 (선택)
```

**첫 줄 방식** (안마다 다르게):
- 결과부터 — "고양이 그림 122장 다시 뽑았다"
- 숫자 — "그림 하나에 1장이면 될 줄 알았는데 4장이 필요했다"
- 반전 — "AI 가 그린 고양이가 너무 귀여워서 다 버렸다"
- 혼잣말 질문 — "고양이를 날씬하게 그려 달라는 게 이렇게 어렵나"
- 비유 — 게임 · 기술 비유 ("레벨 디자인 다시 하는 기분")

## 3. 길이와 모양

- 글 하나 **500자 한도**. 보통 150~350자가 읽기 좋다.
- 길어지면 **이어지는 글**(2~4개)로 나눈다 — 첫 글만 읽어도 이야기가 되게.
- 문장은 짧게, **한두 문장마다 줄바꿈**. 화면에서 숨 쉴 틈이 보이게.
- 연재 표기는 끝이나 첫 줄 앞에 짧게 — "Nyanitor 개발기 #12".
- 링크(저장소 등)는 본문보다 이어지는 글 끝에.

## 4. 주제 태그 · 커뮤니티

- **태그는 글마다 하나** — 계정 README "자주 쓰는 태그" 에서 그 글의 **중심 이야기**에 맞는 것을 고른다. 매번 같은 태그로 고정하지 않고, 목록 밖으로 자주 나가지도 않는다 (계정 성격이 흐려진다).
- 목록에 없는 태그가 확실히 더 맞으면 제안하고, 목록에 더할지 묻는다.
- 본문에 `#…` 를 늘어놓지 않는다. 태그는 올릴 때 태그 칸에.
- **커뮤니티는 맞는 글만** — 그 모임 사람들이 궁금해할 이야기(예: AI 에이전트에게 일 시킨 경험)일 때만 계정 README "커뮤니티" 에서 추천한다. 진행 소식 · 홍보만인 글은 올리지 않는다.
- 쓴 태그 · 커뮤니티는 글 목록에 남긴다 — 반응과 같이 보고 4주쯤 뒤 어느 쪽이 잘 맞는지 돌아본다.

## 5. 말투

계정 폴더의 `voice.md` 가 기준이다. 공통으로:

- 생각이 진행되는 게 보이게 — "처음엔 ~인 줄 알았는데", "근데 해 보니까"
- 한 글에 생각 하나. 아는 걸 다 넣지 않는다.
- 결론은 낸다. 가능성만 늘어놓고 끝내지 않는다.
- 유머는 설명하지 않는다.

## 6. 피할 것

- 자기 과시 ("제가 만든 혁신적인…"), 과장, 가짜 숫자 · 반응
- 공감 구걸 ("공감되시면 좋아요"), 끝마다 질문 붙이기
- AI 티 나는 문장 — "~에 대해 알아보겠습니다", 요약으로 시작하기, 이모지 도배, 모든 문장이 같은 길이
- 내부 용어 그대로 — D-번호, 지시서, P4 같은 말은 풀어서 ("디자인을 다시 정했다")
- 남을 깎아내리는 비교

## 7. 연재로 쌓기

- 프로젝트마다 연재 번호를 잇는다. 이미 다룬 이야기는 다시 쓰지 않는다 (프로젝트 README).
- 가끔은 묶어 보기 — "지난 2주 동안 바뀐 것 3가지" (전후 이미지와 함께).
- 마일스톤(첫 실행, 첫 사용자, 출시)은 미리 알고 준비한다 — 그전 글들이 그 순간을 기대하게.
